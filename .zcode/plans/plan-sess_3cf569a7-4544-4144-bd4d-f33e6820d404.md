## 阶段 P1：健壮性修复

**T1 模型客户端模块级单例**（`app/llm/client.py`、`app/vision/client.py`）
- 问题：`generate_node.py:159`、`translate_node.py:85`、`llm_checker.py:78`、`vision_node.py:21` 每次调用都 new 客户端实例，而 `_get_client()` 缓存是实例级的 → 每请求每节点重建 AsyncOpenAI + httpx.AsyncClient（重新 TLS 握手、旧连接无人 close）。
- 改法：抽共享工厂（按 base_url/key/timeout 缓存 AsyncOpenAI），两个客户端复用；提供 reset 钩子供测试隔离。
- 测试：断言两个客户端实例拿到同一底层 client。

**T2 上传大小先校验后读取**（`app/api/routes.py`）
- `_read_and_validate` 与 `parse_import_file` 的 CSV/Excel 分支：先用 `UploadFile.size` 判 20MB 上限（size 未知时回退现行为），超限直接 400，不再把整个文件读进内存。
- 测试：伪造 size 超限的 UploadFile 断言 400。

**T3 图片压缩移出事件循环**（`app/vision/client.py` `_remote_analyze`）
- `preprocess_image` 循环包进 `run_in_threadpool`，20 张大图不再阻塞事件循环。

**T4 合规复核解析失败兜底**（`app/guardrails/llm_checker.py` + `compliance_node.py`）
- 解析失败先重试一次 LLM 调用；仍失败则 fail-open，但把"语义复核已跳过"写入 `ComplianceResult.warnings`（不再静默）。

## 阶段 P2：合规校验强化（核心价值）

**T5 结构性合规校验器**（新建 `app/guardrails/structural_validator.py`，挂入 `compliance_node`，违禁词扫描之后、LLM 复核之前）
- 违规级（触发重写回环），规则来源 `data/platform_rules/*.md`：
  - 标题长度：amazon ≤200（AMZ-TITLE-01）、shopee ≤120（SPE-TITLE-01）、temu 20–120（TEMU-TITLE-01）
  - bullet：amazon ≤5 条且每条 ≤500 字符（AMZ-BULLET-01）；描述 ≤2000 字符（AMZ-DESC-01）；后台关键词合计 ≤249 字节（AMZ-KW-01）
  - 标题 emoji/装饰符号：shopee/temu；URL/外链：全平台；价格字样：temu（TEMU-PRICE-01）
- 警告级（只展示不触发重写，防误报空转）：标题 ALL-CAPS 词（amazon/temu，内置 USB/LED/HDMI/PVC 等 acronym 白名单）、amazon 标题 `!*$?` 装饰符号、amazon bullet >250 字符建议。
- 违规消息带 rule_id 前缀，经现有 feedback 机制回给 generate 重写。
- 测试：新增 `test_structural_validator.py` 每条规则正/反两向；确认 mock 输出天然合规（现有测试不回归）；`test_agent_graph` 补一条结构性违规触发回环的用例。

**T6 LLM JSON 结构化输出**（`app/llm/client.py`）
- `chat()` 增加 `response_format` 参数；generate/checker/translate 三个调用点启用 `json_object`；保留 `extract_json_object` 容错回退。

**T7 max_tokens 上限**（`app/config.py` + `llm/client.py`）
- 新增 `llm_max_output_tokens`（默认 2048），`chat()` 传入。
